# 章节畅销书化改造工作流

> 当书稿已在 Obsidian 写完（技术/实操风格），需要升级为畅销书格式时使用。

## 适用场景

- 书稿已有完整正文（现状→痛点→AI重构→案例）
- 但缺少畅销书标配的三件套：**决策者摘要 + 延伸阅读 + 落地工具**
- 不想重写正文，只在关键位置插入新元素

## 每章需要补的三个元素

### 1. 决策者摘要（章首）

**位置**：章标题 `# 第X章` 之后、正文第一个内容块之前

**写法**：
- 300字以内
- 面向高管/决策者（不是执行者）
- 先抛出冲击力数据或反直觉结论
- 点明"这一章值不值得看5分钟"
- 以 `> **可带走的一句话**：...` 收尾

**模板**：
```markdown
### 【决策者摘要】

（冲击力开篇——数据/案例/反直觉结论）

（核心观点展开——这一章给出了什么判断/框架）

> **可带走的一句话**：xxx

---
```

### 2. 延伸阅读（章末）

**位置**：本章小结内容之后、📌 配套资源之前

**写法**：
- 3-5条推荐阅读
- 格式：`**《书名》（作者）**— 一句话推荐理由`
- 外2内1结构：至少1条是作者自身专题（公众号/技能）
- 公众号专题加引导语：`公众号回复「关键词」获取`

**模板**：
```markdown
### 【延伸阅读】

- **《外部经典1》（作者）**— 推荐理由
- **《外部经典2》（作者）**— 推荐理由
- **「作者专题名」— 树懒老K·慢读经典专题**— 推荐理由。公众号回复「关键词」获取。
```

### 3. 落地工具（章末）

**位置**：延伸阅读之后、分界线 + 📌 配套资源 之前

**写法**：
- 1个可带走的具体东西（不是概念，是可操作的工具）
- 格式：**工具名称**：一句话说明 → 具体内容（列表/表格/话术/检查清单）
- 必须让读者能"今天就能用"

**常见形式**：
- 检查清单（"做X之前的Y个问题"）
- 话术模板（"不要这样说，要这样说"）
- 计算器公式（"输入A+B得到C"）
- 自评表（"用这个表评估你的现状"）
- 决策矩阵（"什么情况下选A，什么情况下选B"）

## 插入方法

使用 `patch` 工具，每章做两次替换：

### 插入点1：决策者摘要

**old_string**: 章标题 + 正文开头的第一句话（去掉前几个字确保唯一）
**new_string**: 章标题 + 决策者摘要 + 正文开头

示例（第1章）：
```
old = "# 第1章：标题\n\n> 端到端场景"
new = "# 第1章：标题\n\n### 【决策者摘要】\n\n内容...\n\n---\n\n> 端到端场景"
```

### 插入点2：延伸阅读 + 落地工具

**old_string**: 本章小结结束处 + 分界线 + 📌 配套资源（包含足够上下文确保唯一）
**new_string**: 本章小结结束处 + 延伸阅读 + 落地工具 + 分界线 + 📌 配套资源

**关键**：old_string 必须包含足够的唯一上下文（引用上一段结尾的几句话），否则 `---` 和 `📌 配套资源` 会因为多处匹配导致 patch 失败。

### 注意事项

- 第9章/最后一章通常缺"本章小结"——需要额外补
- 使用 `terminal` 的 `sed -n` 或 `tail` 确认精确的插入位置后再写 patch
- 每章的"端到端场景"和"配套资源"之间的结构高度相似，old_string 必须有足够长的独特前缀
- 如果 patch 报 "Found N matches"，增加更多唯一上下文行到 old_string 中

- [ ] 每章都有【延伸阅读】（本章小结后，3-5条）
- [ ] 每章都有【落地工具】（延伸阅读后，1个可带走的东西）
