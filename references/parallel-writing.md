# 并行写书工作流（Parallel Chapter Writing）

> 使用 delegate_task 同时写多个章节，大幅缩短全书写作时间。
> 适用于书稿内容已在 OUTLINE.md 中确认后，批量产出初稿。

## 适用条件

- 全书结构已确认（OUTLINE.md 已完成且用户确认）
- 目标读者、写作风格、植入策略已统一确定
- 用户说"全部写完"或"批量写"时触发
- 每章相对独立（依赖关系弱）

## 分批策略

每批最多 3 个 delegate_task（并发限制），按以下批次分配：

```
批1: 概念+认知篇（第1-3章）
批2: 实操+战略篇（第4-6章）
批3: 案例+收尾篇（第7-9章）
批4: 展望+附录（第10-12章，如有）
```

**实战验证（2026-06-23，《Claude Code工程实战》）：**
- 批1: 第1-5章 ✓ 成功完成（555s, 14 API calls）
- 批2: 第6-11章 ⚠️ 超时（600s），但第6-9章内容已保存，仅第10-11章缺失
- **结论：** 超时批次的中间结果会保留，补写缺失章节即可。如果某批预测会超时，拆为2批（每批3章）。

## 章节重新编号的恢复策略

**铁律：当需要插入新章节导致重新编号时，不要手动 mv 目录——直接重建。** 

已验证的最优方案：
1. 先合并一次当前所有章节 → merged-manuscript.md（作为备份基线）
2. 写新章节
3. 用 Python 脚本从 merged-manuscript.md 中按旧编号提取各章内容，按新编号写入对应目录
4. 清理多余的旧目录

**踩坑记录（切勿重蹈）：**
- ❌ 用 shell `for i in 11 10 9...; do mv chapter-$i chapter-$((i+1)); done` 做批量重命名 → 目录冲突、顺序错乱、内容被覆盖
- ✅ 用 Python `re.split()` 从 merged-manuscript.md 解析出所有章节，按新编号映射写入

## 子agent指令要点

每个 delegate_task 必须包含：

### 内容指令
- 本章标题、小节、目标
- 参考数据（行业数据、案例素材、Skill名称）
- 上一章和下一章的主题（保证衔接）

### 格式指令（MANDATORY — 踩过坑）

```
# 第X章 [章节标题]    ← 必须是 `# ` 单井号！不能是 `## X.1`
                      ← 解析器依赖 `# ` 识别章节边界

## X.1 小节标题       ← 子节用 `##`（双井号）
                      ← `##` 前必须空一行

正文内容...

---

### 本章小结
1. ...

### 📚 延伸阅读
- **专题名称** — 推荐理由
```

### 格式铁律
- ❌ **不能用 `##` 作为章节标题** → 解析器在 merged-manuscript.md 中依赖 `# `（单井号）识别章节边界
- ✅ 每个章节文件必须以 `# 第X章 标题` 开头（单井号）
- ✅ 小节用 `## X.x`（双井号），前面空一行
- ✅ 中英文之间加空格
- ✅ 结尾统一：`---`, `### 本章小结`, `### 📚 延伸阅读`
- ✅ 使用中文引号 ""（非直引号）
- ✅ 文件写入 `~/Desktop/sloth-books/<project>/src/chapter-XX/section-01.md`

## 完成后处理

1. 给每个章节文件补 `# 第X章 标题`（如果子agent忘了加）
2. 重新合并：`merge-book.py <project-dir>`
3. 验证章节数：解析器应检测到 `前言 + N章 + 附录` 共 N+2 个章节
4. 跑审校：`press-review.py --book-dir <project-dir>`
5. 构建：`press-typeset.py --input merged-manuscript.md --preset <theme> --output output/book.pdf`

## 格式铁律

- ❌ 子agent写章节时如果用了 `## X.1` 作为开头（没有 `# 第X章` 前缀），合并后的 merged-manuscript.md 不会识别出独立的章节边界
- ❌ 子agent之间不要共享上下文 → 每个子agent只拿到自己那章的信息
- ✅ 引用数据时可以用 research 阶段的汇总（bibliography.md）
- ✅ 每章内容量：3000-5000字中文为宜
