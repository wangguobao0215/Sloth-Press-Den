# 行业研究 + 实战指南类书籍结构指南

> 适用场景：面向特定行业的 AI/数字化转型实战书籍，兼顾"行业研究"和"落地指南"双重定位。

## 案例来源

本模式提炼自以下验证案例：

- **案例A：医药批发企业AI转型实战**（13章，约42,000字符，2026-05-23）— 面向医药批发企业中高层管理者，行业趋势→案例研究→业务场景→落地规划结构
- **案例B：流程智能——AI重构制造业核心业务链**（12章含附录，约200,000字，2026-05-25）— 面向制造业CIO/IT架构师，APQC标准流程×SAP主线×AI重构，七大流程域逐域展开

## 五部分标准结构（案例A验证）

```
Part 1: 行业趋势研究（为转型建立"为什么是现在"的认知基础）
  第1章 行业变局与挑战 —— 宏观趋势、政策变化、竞争格局、客户变迁
  第2章 AI/技术趋势 —— AI能力演进、行业AI渗透现状、全球对标

Part 2: 案例研究（"别人已经做到了什么"）
  第3章 国内外先行者案例 —— 2-3个国际标杆 + 3-4个国内案例
  （每个案例五维度：转型背景→技术选型→实施路径→核心成效→可复制性）

Part 3: 核心业务场景AI转型实战（全书的"肉"）
  第4-9章（或5-8章不等），每章同一结构

Part 4: 落地规划（"具体怎么干"）
  → 转型路线图（评估→蓝图→三阶段路线）
  → 数据与技术架构（实施基础、中小企业方案）
  → 组织变革与人才培养（岗位转型、培训体系、变革管理）

Part 5: 展望 + 行动建议
  未来趋势 + 给管理者的具体行动建议（5-10条）
```

## 流程重构类书籍的章节模板（案例B验证）

> 与案例A的"行业场景叙事"不同，案例B的类型是"流程域逐域展开"——以行业标准流程框架为骨架，系统落地。
> 适用场景：面向CIO/IT架构师群体，以APQC/SAP等标准流程体系为参照系，逐流程域讲解AI如何重构。

### 全书三篇结构

```
第一篇 · 理论根基（~30页）
  绪论：为什么需要这本书——制造业三次流程范式转移
  第1章：理论坐标系——事务逻辑→数据逻辑的范式转移，双轨优化模型（Flow Doctor），AI能力边界

第二篇 · 流程重构实践（~220页）—— 每个流程域一单章，6-7个域
  每章同一模板（见下方）

第三篇 · 能力与演进（~30页）
  实施路径、ROI评估、组织变革、未来展望

附录：速查表、术语表、配套资源（引流入口）
```

### 每章统一模板（7个流程域验证）

```
现状（系统流程分析）
  ↓
痛点（2-4个核心瓶颈，每个有根因分析）
  ↓
AI重构方案（四色标注+四类嵌入+决策式AI/生成式AI分场景）
  ↓
重构后流程（Before/After对比，L1概览图）
  ↓
实操案例（每章2-3个，含诊断→AI方案→效果→关键经验）
```

**章节模板详解：**

#### 第一段：现状（APQC/SAP为主线，ERP差异做旁注）

- 以该流程域在SAP中的完整事务码链路为主线（如OTC：VA01→VL01N→VF01→F-28）
- 逐节点解释做什么、在哪里卡、为什么慢
- 国内ERP的差异处理：不提具体厂商名称，用功能分类法标注（"财务供应链导向"、"集团管控导向"、"制造深度导向"）
- 典型节奏说明（该流程的"正常"时长 vs "理想"时长）

#### 第二段：痛点（2-4个，量化+根因）

- 每个痛点用数据或场景说明（"报价平均3.5天"、"三单匹配异常率18%"）
- 根因分析要走到"为什么事务逻辑解决不了这个痛点"的层面
- 每个痛点之间要有因果联系（而非并列堆砌）

#### 第三段：AI重构方案（核心方法论工具）

**四色标注系统**（全书统一标注语言）：

| 标注 | 含义 | 例子 |
|------|------|------|
| 🟢 **绿色** | 适合AI完全替代 | 三单匹配、费用审核、安全库存计算 |
| 🟡 **黄色** | 适合AI辅助，人做决策 | 供应商推荐、排产确认、合同审查 |
| 🔴 **红色** | 必须人工处理 | 重大合同签署、客户关系维护 |
| ⚪ **灰色** | 暂不判断 | 信息不足，需更多业务上下文 |

**四类嵌入方式**（与四色搭配）：

| 嵌入方式 | 对应标注 | 示例 |
|---------|---------|------|
| 完全替代：AI自动执行，仅例外转人 | 🟢 | AI自动匹配PO-GR-IV |
| 辅助决策：AI出建议→人确认 | 🟡 | AI推荐供应商→采购经理确认 |
| 辅助生成：AI出草稿→人输出 | 🟡 | AI生成财务报告→CFO审阅 |
| 智能质检：AI事后检查人的输出 | 🟡 | AI复核已审报销单 |

**结构化场景写法：**

1. **决策式AI**——按场景写：什么任务→数据来源→模型类型→输入输出→实施条件
2. **生成式AI**——按场景写：什么任务→输入→输出→限制条件
3. 每类场景说明：重构深度（Phase 1/2/3）、对人影响

#### 第四段：重构后流程

- **Before**：用箭头链式写法展示现状流程，标注主要瓶颈
- **After**：用箭头链式写法展示AI增强后的流程，标注"关键变化"
- 一张L1概览对比图展示"双栏对比"（左Before右After，子流程节点对齐）
- 文字说明3-5个关键变化的本质

#### 第五段：实操案例

每个案例统一结构：

```
**背景**：企业规模+行业+使用系统+核心痛点
**诊断结果**：Track A（精益净化）发现了什么 + Track B（AI介入）的评估
**AI方案**：做了什么+怎么做+实施路径（第1周→第N周）
**效果**：3-5行对比表（改造前 vs 改造后）
**关键经验**：2-3条从这个案例中得到的教训
```

**案例选择原则**：
- 每章2-3个案例，一个SAP企业+一个国内ERP企业（覆盖两类读者）
- 案例要有对比性——不是两个"成功的例子"，而是一个"A方案好不好"、一个"从另一个角度切入"
- 效果数据要有来源说明（系统记录/抽样统计/估算）

### 图表三级交付体系（流程类书籍标配）

| 层级 | 形式 | 内容 | 数量/章 |
|------|------|------|--------|
| **L1 概览对比图** | Mermaid SVG，双栏子流程图 | Before vs After对比，≤8个主节点/侧 | 2-3张/章 |
| **L2 泳道图** | Mermaid swimlane SVG | 跨角色/跨系统的协同流程，≤6泳道×8列 | 1-2张/章 |
| **L3 节点明细表** | Markdown表格 | 逐节点：节点→执行方→输入→动作→输出→AI介入→异常 | 按需，可选 |

**图表渲染方式**：
- 使用 Mermaid CLI (`mmdc`) 编译成 SVG 嵌入
- Chrome 路径：`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`
- Puppeteer 配置：`{"executablePath": "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome", "args": ["--no-sandbox", "--disable-setuid-sandbox"]}`
- 参数：`mmdc -i input.mmd -o output.svg -w <width> -H <height> -b white --puppeteerConfigFile /tmp/puppeteer-config.json`
- 每个diagram的.mmd文件在 /tmp/ 中创建，SVG产出复制到 `assets/` 目录

**Mermaid颜色方案（案例B验证）**：
```css
classDef title   fill:#1A2744,color:#fff      /* 深蓝标题 */
classDef before  fill:#FEF3C7,color:#92400E   /* 浅黄-Before */
classDef after   fill:#E0F2E6,color:#166534   /* 浅绿-After */
classDef pain    fill:#FED7D7,color:#B91C1C   /* 浅红-痛点 */
classDef ai      fill:#DBEAFE,color:#1E40AF   /* 浅蓝-AI */
classDef result  fill:#F3F4F6,color:#374151   /* 浅灰-普通 */
```

### 章节尾部统一模板

每章结束后按此顺序收尾：

```
1. "本章图表"区域（仅流程实践篇）：嵌入L1概览对比图，带图注
2. --- 分隔线
3. "本章小结"：3-5个核心观点，不以"总结"收尾，而以"推向下一章"收尾
4. --- 分隔线
5. 📌 配套资源区域：
   > 本章的[资源名称]可在配套网站下载。
   > 
   > （此处放置个人网站二维码）
   > 
   > 扫码获取 · 树懒老K · 拙一
6. --- 分隔线
7. *第X章完*
```

**引流统一原则**：所有章节的二维码统一指向**个人网站**，不引向GitHub、不引向多个不同入口。读者只需记住一个地址。引流钩子是"获取配套资源"（模板/清单/文件），而非"购买"或"联系"。

## 用户偏好（老K的写作原则）

### 框架选择铁律
- ❌ **不要使用与某个具体客户项目高度绑定的框架**。4A+Agent框架虽有价值，但在为行业写书时容易让读者觉得"这是某某公司的案例"，降低可信度
- ✅ **用更通用的叙事结构**：行业趋势→案例研究→业务场景→落地规划。读者可以直接对应到自己的企业
- ✅ **申远等真实项目可以作为案例提一嘴，但不能成为全书的框架基础**

### 各章内容标配
1. **每个业务场景章必须有「前后对比表」** — 让读者一眼看到AI带来的具体变化
2. **每个业务场景章必须有「实操案例」** — 真实企业案例（脱敏处理）或行业典型场景合成案例（标注说明）
3. **每个业务场景章必须有「关键经验/实操要点」** — 告诉读者从哪开始、要什么条件、有什么坑
4. **数据出处铁律** — 所有数据、案例、引用必须有真实出处标注，不编造URL和来源
5. **每章独立可读** — 读者可以从最关心的流程域开始读，不需要按顺序。每章共享同一套方法论语言（四色标注、嵌入方式、双轨模型），但每章的案例和痛点自成闭环

### 写作流程
1. Phase 1: 确认书名/副标题/目标读者/章节数 → OUTLINE输出
2. OUTLINE经用户批准后再进入Phase 2/3
3. **先出绪论+第一章校准调性**：写整本书前先写开头章节给用户看调性。用户点头再铺后面。这比全写完再大改省10倍返工量。（用户原话："A：我先出绪论+第1章全文，你先看调性、深度、语言风格对不对胃口。对了再铺后面。" → 答："A"）
4. 每章先写文字稿，文字内容定稿后再做Mermaid图（因为图的节点数和分支取决于具体案例）
5. 每章写完后立即更新 BOOK_SUMMARY.md（500字以内压缩摘要）

### 流程陷阱
- ✅ 每章写完后确认"本章图表"区域是否能找到对应的SVG文件（assets/目录下）
- ✅ 每次生成新图后，SVG文件名要在第X章.md 和 assets/ 目录之间保持一致性
- ❌ 不要在初稿中写死关键数字 → 用 `XXX万`、`YYY元` 等显式占位符，写完后问用户是否需要统一替换
- ❌ 不要事先为没写的章节做图 → 文字可能调整导致节点变化，图需重做

## 本书的叙事线（参考两种模式）

### 模式A：行业趋势→案例→场景→规划（案例A，场景中心）
```
Part 1（行业趋势研究：第1-2章）
→ Part 2（案例研究：第3章）
→ Part 3（六大业务场景AI实战：第4-9章）
→ Part 4（落地规划：第10-12章）
→ 未来展望（第13章）
```

### 模式B：理论→流程域逐域展开→能力演进（案例B，流程中心）
```
第一篇 理论根基（绪论+第1章）
→ 第二篇 流程重构实践（第2-7章，六域：计划→OTC→P2P→生产→仓储→财务）
→ 第三篇 能力与演进（实施路径+组织变化+未来展望）
→ 附录（速查表+术语+配套资源）
```

每个业务场景章独立可读，适合读者只翻看自己关心的场景/流程域。但连起来构成一条从认知到行动的完整链。

### 案例A：医药批发企业AI转型实战（2026-05-23）

| 指标 | 数值 |
|------|------|
| 书名 | 医药批发企业AI转型实战——从传统批发到智慧供应链 |
| 章节数 | 13章 |
| 总字符数 | ~42,000字符 |
| 写作时长 | ~1.5小时（9章核心场景 + 4章规划展望） |
| 输出 | PDF（雾霁蓝预设，2.5MB）+ Markdown书稿 |
| 作者 | 树懒老K（拙一） |

**流程验证：**
1. Phase 1: OUTLINE经用户确认（3轮迭代：去掉申远框架→品牌/市场场景→渠道销售2B2C）
2. Phase 2: refs.md研究笔记（每章一个，~200-500字）
3. Phase 3: 一次性写完13章（先写1-3章奠定叙事基调，再写4-9章核心场景，最后10-13章收尾）
4. Phase 4: press-review 审校（78 issues，主要为空术语表和排版间距）
5. Phase 5: merge-book → press-typeset → PDF输出

**关键成功要素（案例A）：**
- ✅ OUTLINE经用户充分确认后再写（3轮过审，不是1轮）
- ✅ 每章refs.md先写（让思路清晰后再动笔）
- ✅ 核心场景章保持统一格式（场景还原→AI改造→前后对比→案例→实操要点）
- ✅ 写完即更新BOOK_SUMMARY.md

### 案例B：流程智能——AI重构制造业核心业务链（2026-05-25）

| 指标 | 数值 |
|------|------|
| 书名 | 流程智能：AI重构制造业核心业务链 |
| 章节数 | 9章 + 3个附录 |
| 总字数 | ~200,000字 |
| 图表 | 11张Mermaid SVG（L1对比图×7 + L2泳道图×1 + 理论图×3） |
| 案例数 | 15个实操案例 |
| 写作时长 | 单次会话（约4小时，写作+制图+嵌入） |
| 输出 | Markdown书稿（Obsidian vault） |
| 作者 | 树懒老K（拙一） |

**流程验证（案例B）：**
1. Phase 1: 快速讨论确认主题方向 → 6轮对话迭代（理论骨架→读者定位→国内ERP模糊化→引流统一→书名确认）
2. Phase 1校准：先出绪论+第1章给用户看调性 → 用户确认"基本可以"后铺全量
3. Phase 3: 按流程域顺序一次性写完所有章节（6个流程域逐章写+图+嵌入）
4. 每章写完即时嵌入图（L1对比图），保证文字和图的一致性
5. 全书写完后统一做附录

**关键成功要素（案例B）：**
- ✅ 先出开头章节校准调性 → 减小全稿返工风险
- ✅ 每章的"统一模板"在Phase 1就定死（现状→痛点→AI重构→重构后流程→案例）→ 写作过程中不需要纠结结构
- ✅ 文字和制图分开做：先写完全文，再统一做图（因为图依赖具体案例内容）
- ✅ L1对比图的.mmd模板代码在不同章节间高度复用（改节点名+颜色即可）
- ✅ 引流统一指向个人网站（非GitHub/非多入口）
